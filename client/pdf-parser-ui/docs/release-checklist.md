# Release check / QA checklist

Короткий чек перед демо и релизом.

## 1) Какие команды запускать

Выполнить из `client/pdf-parser-ui`:

```bash
npm run test
npm run build
npm run test:e2e
npm run release:smoke
```

Дополнительно (если есть серверные изменения) из `server/pdf-parser`:

```bash
npm run build
```

## 2) Что проверить вручную перед демо/релизом

Основа ручной проверки описана в `docs/release-smoke-checklist.md`. Минимальный прогон:

- Вход/выход и корректный редирект по роли.
- Создание документа и отображение в списке.
- Отправка на согласование и обновление статуса.
- Решение по задаче согласования (минимум 1 сценарий).
- Админ-панель: чтение списков + одно безопасное действие.
- Ошибки API: есть понятный текст, кнопка `Повторить`, fallback-действие.
- Responsive sanity-check: desktop + мобильная ширина (таблицы/действия/модалки).

## 3) Критерии “готово к релизу”

Релиз считается готовым, если одновременно выполнено:

- Все CI шаги по client проходят (`test`, `build`, `test:e2e`).
- Smoke-checklist выполнен без блокирующих дефектов.
- Нет P0/P1 багов в критических флоу: вход, документы, согласование, админ-действия.
- Нет регрессий в empty/loading/error состояниях ключевых страниц.
- Нет новых TypeScript/lint ошибок в измененных файлах.

Если хотя бы один критерий не выполнен — релиз блокируется до исправления.
